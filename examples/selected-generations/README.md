# Coherent selected generation examples

Run each example into a new disposable directory. The fixtures use public synthetic
inputs, actual Git repositories and local bare destinations. They never install a
shared/default package or invoke a live host/provider.

```sh
python3 -B examples/selected-generations/run.py --case independent --output cache/generation-independent
python3 -B examples/selected-generations/run.py --case siege --output cache/generation-siege
python3 -B bin/_test/selected_generation_test.py
```

Each example first runs the accepted selected registration oracle, then stages the
same package through `package-generation.py stage-selected`, registers a consumer
through install/wire/verify with `--generation-store`, upgrades project content (independent) or scaffold code (Siege) and
rolls back. The emitted `generation-evidence.json` records complete inventories,
identities, policy observations, local decisions and epochs. Baseline package bytes
must match the normal registration output, and rollback must match every retained
source/content/settings/native byte while producing fresh receipts. The Siege
oracle also compares the full legacy exporter inventory, executable modes, settings
payloads/group metadata, wrapper vectors and effective-policy explanations.

The independent source physically omits Siege bundles and legacy skills/hooks/
examples/defaults before the normal builder runs. The transition tests separately
add a qualified synthetic Siege skill without workflow adoption and prove that
no Siege ticket/review/branch ceremony activates. The same tests upgrade a content
bundle, scaffold, project, policy and registration definition independently;
source components not being upgraded retain their exact revision/digest. A changed
component requires resealing the complete registration pairing with a separately
supplied pin. That reseal is consistency evidence, not a new policy adoption.

## Complexity accounting

This dependency removes zero additional hardcoded policy values or content files.
It removes one unconditional release-handoff source dependency from generation
module loading; the release staging path still loads that verifier.
There is one generation state machine, one atomic current.json selector, one
selected builder, one composer and one effective-policy evaluator. None is duplicated.
The selected source closure adds the existing package-generation.py module so a
physically independent registered package can resolve the existing generation store.

Zero active settings/native files are rewritten during a generation switch. The
existing install/wire/verify APIs share the existing registration implementation;
only bootstrap uses its existing two-file journal. Both generated native wrappers
retain the existing native dispatcher. Settings add stable index dispatch into the
verified selected template; no arbitrary executable discovery is introduced.

The independent example injects one project review skill and zero Siege content
files. The content-only fixture adds one qualified synthetic Siege skill. The
example evidence records full package and rollback file counts/digests directly
from inventories. Source bytes, generated bytes and compatibility bytes are counted
separately rather than treating a directory move as deletion.

Retained compatibility from the accepted dependencies: one full exporter, three
legacy native bodies, one named Siege export function, one fixed strict-release
restriction, one protected-range compatibility wrapper, and two range translators.
The selected Siege adapter still supplies its complete compatibility inventory.
These paths remain measured debt for #849; this change does not claim their removal.
Previous extracted inputs and removed injections are recorded in the
[selected-build](../selected-build/README.md) and
[selected-registration](../selected-registration/README.md) complexity ledgers.
