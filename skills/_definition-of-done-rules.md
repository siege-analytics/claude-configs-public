# Definition of Done

Work is done when the requested outcome is delivered and supported by evidence appropriate to its consequences. Completing a checklist, preparation artifact or dispatch does not establish that outcome.

## Required checks

- **Correct behavior:** inspect the actual change against the original request. Cover relevant boundaries and failure modes; do not mechanically enumerate irrelevant cases.
- **Validation:** run meaningful checks proportionate to the change. Bug fixes need a regression that demonstrates the defect where practical. Do not add tests that merely mirror implementation or demand new test infrastructure for a reversible low-impact edit.
- **Review:** review the diff and resolve material findings. Use [skill:self-review] for proportional records and real independent review of high-risk changes. Required repository CI and actual owner-reserved approvals remain binding; human approval and bot availability are not universal additional gates.
- **Delivery:** publish by the authorized normal workflow. Update an existing ticket or PR with what changed, validation and any remaining limitations. An authorized operational task or clear user request does not universally require a new issue before work may begin.
- **Actual outcome:** for runtime work, verify current behavior in the intended environment. For unattended goals, verify working handoffs and continuation until completion or a genuine whole-objective stop condition.

Update relevant documentation and declared knowledge bases when the change invalidates them. Decompose work when distinct ownership or delivery boundaries help execution, not merely to create more tickets.

A real action-specific hold blocks that action. Continue eligible work and arrange a supported return route. Do not claim completion while required work remains, and do not keep an otherwise finished finite task busy merely because its parent goal continues.
