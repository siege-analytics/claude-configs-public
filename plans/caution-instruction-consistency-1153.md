# Caution instruction consistency (#1153)

## Assumptions

The operator requested consistent instructions about caution. Existing task authority covers ordinary methods and preparation; it does not authorize a new outcome, role, destructive consequence or release of an explicit owner hold. Existing review, CI, branch topology and explicit design sign-off remain prerequisites. No executable gate or classifier changes are included.

The audit found contradictory directions across resolver entries, skill bodies and checklists: repeat main-merge approval, missing-review waiver requests, global decision-list waits, unconditional design choices reserved to the user, routine conflict confirmations and repository-wide signal cleanup despite task-owned gates.

## Design

Use a bounded prose correction in the existing instruction chain. Retaining only the stronger autonomy paragraph would leave contradictory checklists and companions. Removing preparation/review gates would change authority and is rejected. A new workflow engine or override flag is unnecessary.

The selected behavior is: inspect existing authority and evidence, complete missing prerequisites within the assigned role, choose routine methods, and proceed. Ask for the specific unresolved material decision; hold only the dependent action. Silence cannot supply missing authority. An explicit hold ends only by the owner or its stated release condition.

Task signals remain owned by session and task, not by repository alone. A new task does not require deleting another task's gate. Cleanup preserves active work, terminal evidence and canonical claims. In-use branches and branches designated for retention are not deleted as a condition of declaring a merge complete.

## Risks and verification

- Over-broad autonomy could skip required review, role changes or a named design sign-off. Independent scenarios retain those stops.
- Under-broad wording could leave a stale checklist or companion requesting repeated permission. Review covered bodies, examples, checklists, design entry/exit and the self-review companion.
- Generated layouts could retain older instructions. Rebuild both layouts and regenerate inventory, authority, budget and loading metrics through existing tools.

Independent read-only instruction evaluation exercised authorized releases across turns, missing review, routine conflicts, review-only work, independent slices, project dependency setup, owner holds, requested public behavior, authorized and unauthorized integration repair, failed CI, silence, explicit design sign-off, new production data-loss risk, coexisting same-repo tasks, retained branches and conditional holds. Earlier draft evaluations found contradictions; their corrections were reread. This is instruction-level evaluation, not model/backend callback proof.
