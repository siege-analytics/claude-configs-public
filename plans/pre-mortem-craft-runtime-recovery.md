# Pre-mortem: Craft runtime recovery

Goal source: plans/craft-runtime-recovery.md

The investigation and original risk analysis are recorded in that design note.
This artifact preserves the mitigation/verification links for the repair.

1. Mixed runtime markers could downgrade a standalone process. Require the exact
   OS-observed installed Craft ancestor; unknown hosts, failed process probes,
   unrelated processes, and lookalike temporary paths retain blocking. Covered
   by ca_enforcement_runtime.test.sh.
2. An installation could again ship a root-only manifest. The builder now copies
   the colocated manifest, the verifier requires it without assertions, and drift
   checking compares its generated bytes. Missing and optimized-Python negative
   cases are in verify_enforcement.test.sh and check_deploy_drift_test.py.
3. Commit-message modeling could accept a ticket Git removes or omit one Git
   keeps. Insert trailers before cleanup using a frozen non-executable config
   snapshot, honor custom comment prefixes and edit-dependent scissors, and
   compare with actual disposable commits. Do not execute trailer commands.
4. Broad deployment could erase task state or enable unwanted automations.
   Install a backed-up runtime overlay; preserve sessions, task signals,
   settings, automations, and instruction files. Record per-file hashes and
   rollback copies outside the source repository.
5. Package tests can misdiagnose uncommitted tool changes as provenance drift.
   Test immutable generation after a local checkpoint commit; use physical
   temporary paths on macOS for symlink-sensitive registration tests.
