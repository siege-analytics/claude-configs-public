## Assumptions

The local journal is trusted coordination metadata, separate from #848/#851
policy, capability and authorization inputs. The caller publishes checkpoints
and verifies external receipts. Configurable budgets remain subordinate to host
instructions. Generation fencing covers writes to this journal only. Superseding
an owner cannot cancel its tools, grant permissions or authenticate identities.

## Lead review

Reviewed changed-head resets, separate check/finding state, duplicate receipt
handling, interrupted work, one current owner, optimistic concurrency and CLI
read-only behavior. An exhausted class suspends that approach in the displayed
state; independent work remains available. The helper cannot mechanically
prevent edits, deliver messages or enforce a wall-clock timeout. Documentation
and output identify these limits explicitly.

Removed an import-generated bytecode artifact from the skill source tree and
disabled test bytecode writes so generated authority covers only portable assets.
Both packaged skills carry the same helper without changing the builder.

## Quantified claims

Twenty focused scenarios pass locally. The synthetic journal reports a queued
review, never acceptance. The build packages three owned files for the drive
skill in each layout. Full-suite results and hosted CI are recorded in the PR;
this document does not assert they passed before terminal evidence exists.

Follow-up self-review corrected ambiguous history: invalidation now marks the
original receipt instead of appending a second copy with a different validity
flag. An invalidated receipt cannot become current again after finding resolution
or returning to a previous SHA; fresh review evidence is required.

R1 makes finding resolution one-way; R2 consumes a material receipt sequence
before restarting a chunk (timestamps alone lose same-second events); R3 rejects
rejected/failed/open-finding review handoffs while exposing pending CI separately;
R4 counts distinct candidate heads per failure class, not evidence-array edits.

## Canary and rollback

Disposable journals exercise atomic update, retry and restart; reads leave bytes
unchanged and failed writes preserve the last valid journal. Remove the helper
invocation to return to the existing coordination protocol; no installed runtime,
shared workspace, protected branch or release state changes in this pilot.
