## Lead review

The persisted-state design uses a pending journal, per-registration flock, Git
config lock, staged bytes, original-state comparisons and two replacements.
All newly registered settings/native dispatch checks the journal before running.
Ordinary failures restore replaced bytes without overwriting a detected foreign
edit. Process interruption leaves a recoverable, unusable registration; explicit
recovery validates old/new bytes and foreign locks before restoring prior state.
This provides recovery after process death, not multi-file atomic visibility or a
power-loss durability guarantee. The DDIA derived-data distinction is preserved:
Git source objects and independently adopted policy are the inputs; packages and
configuration receipts are rebuildable observations. Local hooks remain bypassable.
Persisted-state score after the kill/recovery probes: 8/10 for this bounded local
contract; the remaining limitations above are explicit, not provider guarantees.
