The mapping is a navigation document. Do not copy detailed policy into this table. Where owners still overlap, resolve one concern in a scoped follow-up rather than adding another always-on rule.

## Authoring and generated delivery

Maintain shared procedures once. Project overlays contain their actual project constraints. Supporting references contain conditional detail and historical reasoning. Existing inventory, source-authority metadata and package receipts describe the generated projections; they are not independent authoring sites or authorization.

For CraftAgents, discovery remains flat: one public skill directory and one SKILL.md entrypoint per selected skill. The build may compose a shared procedure and a project policy into that one file. Keep one frontmatter block, resolve references for the delivered layout and record the source inputs. A nested authored tree does not require a nested runtime discovery tree.

Authored overlays must live outside generated output paths. Rebuilding must be deterministic and must never recapture yesterday's generated instruction as a new source. Preserve existing entrypoint names while migrating their implementation.

## Migration order

1. Prove the shared merge procedure with a narrow ElectInfo policy and a portable flat artifact.
2. Consolidate Think/authorization decisions and review/evidence detail.
3. Consolidate coordination/delegation and deployment/recovery navigation.
4. Expand to more clients after one active client passes source, package and delivery checks.

At each slice, track which duplicate decisions disappear and which compatibility paths remain. A reduced line count alone is not acceptance.

Think has one discoverable entrypoint. Its ordinary sibling Markdown references carry design, task evidence/lifecycle and verifiable claims detail in both layouts. Pre-edit mutation tiers and commit-review tiers are distinct checkpoints; navigation does not waive authored preparation, grant authority or release owner holds.
